# Aranya CRM 系统重新设计 - 概览


## 一、系统模块总览

1. 🏠 工作台 Dashboard：快速操作、活跃个案、待关注个案、预约
2. 👤 僧人档案 Clients：基于 Master Contact List 的 72 列
3. 📁 个案管理 Cases：基于 Case Number Key 的 48 列
4. 📝 探访报告 Reports：基于 Engagement Report 的 17 列

流程：Dashboard -> Clients -> Cases -> Reports

## 二、角色权限矩阵

| 功能模块 | Social Worker | 志愿者 Volunteer |
| --- | --- | --- |
| 僧人列表（基本信息列） | ✓ 可查看 | ✓ 可查看 |
| 僧人完整档案（全部字段） | ✓ 可查看 | ✗ 不可见 |
| 僧人基本信息视图 | ✓ 可查看 | ✓ 可查看 |
| 创建/编辑僧人 | ✓ 可操作 | ✗ 不可见 |
| 个案列表 | ✓ 可查看 | ⚠ 显示但禁用 |
| 个案详情 | ✓ 可查看 | ✗ 不可见 |
| 创建/编辑个案 | ✓ 可操作 | ✗ 不可见 |
| 添加个案记录 | ✓ 可操作 | ✗ 不可见 |
| 提交探访报告 | ✓ 可操作 | ✓ 可操作 |
| 查看探访报告（全部） | ✓ 全部可见 | ⚠ 仅自己提交的 |

## 三、志愿者可见的“基本信息”字段

法名（中/英）、缩写、联系电话、首选联系方式、首选语言、区域（非详细地址）、佛教传承、戒别（Bhikkhu 等）、会员状态（Active/Inactive）。

**不可见字段：** NRIC、完整地址、出生日期、健康评估、特殊需求、财务信息、近亲联系人等。

## 四、个案颜色编码说明（来自 Case Number Key）

| 颜色 | 含义 | 说明 |
| --- | --- | --- |
| RED | 紧急 Critical | 需要立即关注和干预的个案 |
| ORANGE | 高风险 High Risk | 需要密切监护的高风险个案 |
| YELLOW | 中等 Moderate | 需要定期跟进的中等风险个案 |
| GREEN | 稳定 Stable | 状态稳定，常规跟进即可 |
| GREY | 低活跃 Low Activity | 低优先级或暂停中的个案 |
| BLACK | 已关闭 Closed | 已完成并关闭的个案 |

## 五、页面路由结构

| 路径 | 页面 | 访问权限 |
| --- | --- | --- |
| `/dashboard` | 工作台 | 需登录 |
| `/clients` | 僧人列表 | 需登录 |
| `/clients/new` | 新建僧人 | 仅 Social Worker |
| `/clients/:id` | 僧人详情 | 需登录（内容按角色区分） |
| `/clients/:id/edit` | 编辑僧人 | 仅 Social Worker |
| `/cases` | 个案列表 | 仅 Social Worker |
| `/cases/new` | 新建个案 | 仅 Social Worker |
| `/cases/:id` | 个案详情 | 仅 Social Worker |
| `/reports` | 探访报告列表 | 需登录 |
| `/reports/new` | 提交探访报告 | 需登录 |
